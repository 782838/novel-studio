# 小说创作工作台 Novel Studio

一个本地运行的小说辅助创作工具：**大纲会长期记住并按上下文补全**，角色有完整档案与关系网，主副线路按泳道推进，右侧常驻的 AI 助手不只是陪聊——它能**直接读写你的项目数据**。

![总览](docs/images/view-dashboard.png)

九个模块（总览 / 大纲 / 角色集 / 线路 / 章节 / 设定 / 伏笔 / 备忘 / 素材箱）通过"关联"串成一体；AI 助手有 15 个工具，能真的替你改写大纲、补节拍、建角色。

> **完整功能解析（每个模块的截图与说明）见 [docs/功能解析.md](docs/功能解析.md)。**

零依赖、零构建：只用 Node 内置模块，数据落在本地 `data/store.json`。

> 运行时代码依然是**零依赖**的。只有"打包成安装包"这一步需要临时装 Electron 构建工具（见文末），且构建产物与本机环境无关。

## 打包成桌面安装包（给不装 Node 的电脑用）

把工作台打成一个 Windows 安装包（`Setup.exe`）：**目标电脑不需要装 Node、不需要浏览器、也不依赖任何其它软件**，双击安装后从开始菜单或桌面图标直接打开一个原生窗口。

```bash
npm install                 # 装构建工具（electron / electron-builder）
npm run dist                # 产出 dist/小说创作工作台-安装包-1.0.0-setup.exe
```

产物与要点：

- 安装包在 `dist/`，约 80–100 MB；双击按向导安装（**按用户安装，不需要管理员权限**）。
- 应用数据存在 `%APPDATA%/小说创作工作台/data/`，重装/升级不会丢；卸载默认也保留。
- 首次启动若数据为空，会自动铺一份示例作品《雾隐城》。
- 内置服务端用**系统分配的随机空闲端口**，不会和你机器上其它服务抢 5367/5368。

想改图标：编辑 `build/make-icon.js` 后运行 `npm run icon` 重新生成 `build/icon.ico`。

打包相关的其它脚本：

| 命令 | 作用 |
| --- | --- |
| `npm run icon` | 重新生成应用图标（纯 Node 画的，不依赖图形库） |
| `npm run smoke` | 冒烟测试"内嵌运行"配置（随机端口 / 静态资源 / 数据目录） |
| `npm run smoke:packaged` | 启动已打包的程序，验证窗口能开、接口能通 |

> 打包机器上需要 Node（只是构建用）。**装好的那台电脑不需要 Node**，也不需要浏览器。
> 若下载慢，可先设置镜像再打包：
> `set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`
> `set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`

## 快速开始

要求 Node ≥ 18（用到全局 `fetch` 与 ES Module 前端）。

### 两端分开跑（推荐）

同一份代码可以跑出**两个完全隔离的实例**——各自的数据目录、各自的端口、各自的模型设置，互不干扰：

| | 启动方式 | 端口 | 数据目录 | 特点 |
| --- | --- | --- | --- | --- |
| **写作端**（自用） | 双击 `启动-写作.bat` | 5367 | `data-work/` | 你的真实草稿，空库 |
| **展示端**（演示） | 双击 `启动-展示.bat` | 5368 | `data-demo/` | 首次启动自动载入示例作品《雾隐城》 |

两端**可以同时开着**，也可以在任意一端里操作而完全不影响另一端。这样演示给别人看时，既不会暴露你的未定稿，也不会被人误改。

命令行等价写法：

```bash
node server/index.js 5367                                    # 写作端
node server/index.js 5368 --data=data-demo --seed --open     # 展示端
```

macOS / Linux：

```bash
./启动.sh                          # 写作端
./启动.sh 5368 data-demo --seed    # 展示端
```

### 启动参数

```
node server/index.js [端口] [--data=<目录>] [--seed] [--open]
```

- `--data=<目录>`　指定数据目录。这是多实例隔离的关键，目录不存在会自动创建
- `--seed`　该实例下**还没有任何作品时**，自动载入示例作品《雾隐城》
- `--open`　启动完成后自动用默认浏览器打开

> `--seed` 只在空库时生效，所以展示端即便反复重启，也不会把你改过的演示内容冲掉。想彻底重置演示数据，直接删掉 `data-demo/store.json` 再启动即可。

> 控制台提示「端口已被占用」时：说明该端口已经有一个实例在跑。两个端用的是不同端口，正常不会冲突；如果写作端冲突，关掉那个窗口再试。

首次进入可以点「载入示例作品」，会生成一部《雾隐城》的完整骨架（大纲、3 个角色+关系、3 条线路+节拍、4 个伏笔、设定与备忘），方便先摸清楚各模块怎么配合。

## 九个模块

| 模块 | 解决什么问题 |
| --- | --- |
| **总览** | 作品信息、写作进度环、六项关键指标，以及六个常用提问入口 |
| **大纲** | 无限层级的树（幕/章/场景/节拍）。拖拽即可改变父子层级，右侧是选中节点的详情编辑区 |
| **角色集** | 十项字段的角色卡（动机、弱点、弧光、转折）。可切换**关系图**，环形布局展示人物网络 |
| **线路** | 主线/副线/感情线/悬念线/成长线的**泳道视图**，每条线下挂节拍，节拍可关联到具体大纲节点 |
| **章节** | 分栏写作器，自动保存、实时字数、可挂靠大纲节点，支持 AI 续写与 AI 生成细纲 |
| **设定** | 按「地理/历史/规则/势力/物品/习俗/种族」分组的世界观条目 |
| **伏笔** | 登记表中的每一颗子弹，标记「已埋 / 已回收」，写多了不会忘了收 |
| **备忘** | 灵感、待解决问题、零散设定，支持置顶 |
| **素材箱** | 把其他 AI 平台上的历史对话搬进来，再让助手提炼成结构化内容 |

## AI 助手：能思考，也能动手

这是和其他"聊天框"最大的区别——助手通过**函数调用**直接操作你的数据，最多连续执行 8 轮。

它能调用的工具：

```
create_outline_node / update_outline_node      补写、改写大纲
create_character / update_character            建立与深化角色卡
create_relation                                建立人物关系
create_plot_line / create_beat                 拉出故事线并铺设节拍
create_chapter                                 生成章节条目
add_foreshadow / add_world_item / add_note     登记伏笔、设定、备忘
get_project_context                            重新拉取全部上下文
```

所以你让它「帮我把主线补齐」，它不会回你一段建议让你自己抄——它会真的把节拍建出来，并在气泡下方列出`已执行 N 项操作`的清单。

### 配置模型

右上角 **设置 → 模型**。任何 OpenAI 兼容接口都可以：

| 服务商 | 接口地址 | 推荐模型 |
| --- | --- | --- |
| **智谱 GLM** | `https://open.bigmodel.cn/api/paas/v4` | **`glm-5.3-flash`** |
| 智谱 GLM（旗舰） | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3` |
| Z.ai 国际版 | `https://api.z.ai/api/paas/v4` | `glm-5.3-flash` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-pro-32k` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Ollama 本地 | `http://localhost:11434/v1` | `qwen2.5:14b` |

> 注意：上面阿里百炼的地址请以官方最新文档为准。

设置面板里有「测试连接」，会返回延迟。还有一项 **助手人格 / 写作偏好**，这段文字会进入系统提示词长期生效——比如写上"讨厌巧合推动剧情""所有建议必须落到具体章节"，它会一直照做。

### GLM-5.x 的两个注意点

GLM-5.3 / 5.3-Flash **思考无法关闭**，每次调用都会产出思考 token 并计入输出费用。另外官方推荐温度为 `1`，并且 `reasoning_effort` 支持 `low / high / max` 三档——**不传时默认落到 `max`**，输出会明显更长、更慢、也更贵。

要压下来，在设置面板的 **高级请求参数（JSON）** 里填：

```json
{ "reasoning_effort": "low" }
```

日常做规划、提炼素材这类任务建议 `low`；需要做深度情节推演时再手动改成 `high`。温度也可以顺手调到 `1`。

**未配置 Key 时也不会卡住**：助手进入演示模式，照样能跑通整个"生成→勾选→应用"的流程，产出的是标注过的占位内容。

**模型不支持函数调用时**：会自动降级为 JSON 文本协议——助手在正文里写的 ```json 操作块``` 会被系统**真正执行**，执行结果回传给模型继续推演，功能一样不丢，只是轮次会多一些。界面会显示「已自动切换为文本协议」。（这类模型很常见，比如 deepseek 系：接口收得下工具参数，模型却不会用。）

### 回答可以随时停，思考过程看得见

- 助手回答时，发送按钮会变成 **「■ 停止」**——点它就中止这次回答。**已经生成的部分、已经执行的操作都会保留**，不会白等。
- 推理模型（GLM、DeepSeek 等）的**思考过程会实时展开显示**，并标注思考耗时；回答结束后这条记录仍可点开回看（思考过程与耗时一并存进本地对话记录）。
- 回答逐字流出，连接每 10 秒一次心跳，长时间思考也不容易被掐断。

## 改名与删除作品

- **作品改名**：顶栏「✎ 改名」，或直接在总览页改标题输入框——顶栏下拉框会同步新名字。
- **大纲节点改名**：在大纲树里**双击标题**就地改名（鼠标悬停时行尾也有 ✎ 按钮）。
- **删除作品**：顶栏「🗑 删除」。删除前会显示该作品的章节数与字数，**需要手动输入作品名确认**；章节、大纲、角色、线路、伏笔、设定、素材等关联数据一并清理，其它作品不受影响。

## 素材箱：把别处的对话搬进来

如果你之前一直在别的 AI 产品里构思，那些对话其实是你最值钱的原始素材。素材箱就是用来接住它们的。

**支持的输入**：

| 输入方式 | 说明 |
| --- | --- |
| JSON 文件 | 平台导出的原始文件。解析器会递归找 `messages` / `conversations` / `turns` 等字段，多种嵌套结构都能识别 |
| Markdown | 用标题分段、`**用户**：` / `**助手**：` 这类写法 |
| 直接粘贴 | 从网页上选中复制即可，认 `我：` / `用户：` / `GLM：` / `助手：` 等常见标记 |

操作流程：**素材箱 → ＋导入外部对话 → 粘贴或选文件 → 解析 → 勾选 → 导入**。解析后会先列出识别到的每一段对话，确认无误再落盘。

**导入之后怎么用**：点卡片上的 **✨ 让 AI 提炼**，助手会先用 `read_material` 通读全文，再把角色、设定、情节线索、伏笔分别创建到对应模块，并告诉你它采纳了什么、丢弃了什么、为什么。上下文里只放素材的标题与预览，全文按需拉取，不会一上来就把 token 吃光。

### 怎么把对话从智谱清言里弄出来

这里要说清楚一件事：**智谱清言（消费级聊天产品）和智谱开放平台（open.bigmodel.cn）是两套体系**。开放平台只有"调用模型"的能力，没有读取清言账号历史会话的接口——所以"一键同步账号数据"目前没有合规的实现路径，任何声称能做这件事的第三方，本质上都是要你把登录凭证交出去。

可行的正当办法，按推荐顺序：

1. **看官方有没有导出**：进智谱清言的设置，找"历史记录与存档"相关入口，看是否提供"导出对话/批量导出"。
2. **用本地导出的浏览器扩展**：社区里有导出插件（例如 Z.ai Chat Exporter），全程在浏览器本地完成、不上传数据，可导出 JSON / Markdown / TXT。导出后直接拖进素材箱。
3. **手动复制粘贴**：对话不长的话，直接在页面上框选复制，粘进素材箱的文本框即可——解析器认这种格式。
4. **以后就在这里聊**：新建的对话本来就存在项目里，不用再搬一次。

> 提醒：不要把自己的账号密码、Cookie 或登录态凭证填给任何"一键同步"工具。数据同步这种事，值得多走一步手工流程。

## 生成类功能的统一流程

大纲补全、AI 生成角色、AI 梳理线路、设定补全、脑暴，走的都是：

> 填需求 → AI 生成 → **勾选列表预览** → 应用

预览阶段逐条确认再落盘，避免一次性灌一堆垃圾进项目。

## 目录结构

```
novel-studio/
├─ server/            零依赖服务端
│  ├─ index.js        HTTP 服务 + REST 路由 + Markdown 导出 + 多实例启动参数
│  ├─ store.js        JSON 持久化仓库（防抖写入、原子落盘、损坏自动备份）
│  ├─ ai.js           模型调用、15 个工具的执行器、多轮 Agent 循环、演示模式降级
│  ├─ novel-import.js TXT 分章器（中/英/特殊标记，中文数字章号）
│  └─ sample.js       示例作品《雾隐城》的种子数据（两端共用同一份）
├─ public/            前端（原生 ES Module，无构建）
│  ├─ index.html
│  ├─ css/app.css
│  └─ js/  app.js（状态与路由）views.js（九个视图）agent.js（助手面板）
│        ui.js  api.js  importer.js（外部对话解析）
├─ electron/main.js   桌面端主进程（内嵌服务 + 原生窗口）
├─ build/             构建与测试脚本（图标生成、截图、冒烟测试）
├─ docs/              功能解析文档 + 界面截图
├─ data-work/store.json    写作端数据 ← 你的真实草稿（已在 .gitignore 中排除）
├─ data-demo/store.json    展示端数据 ← 演示内容（已排除）
└─ 启动-写作.bat / 启动-展示.bat / 启动.sh
```

数据只在本机：唯一的外网请求是你自己配置的模型 API。

两个数据目录完全独立，备份时按需拷贝即可——写作端的 `data-work/store.json` 是你唯一不能丢的东西。
